# 人工复核到变动审核的优化检查点

## 目标

人工复核完成后，用户可以上传人工确认的阶段文件，并使用人工确认后的最新 codebook 直接进入变动审核。初始匹配、人工候选卡片、变动审核和 post_rank 审核保持阶段边界，不重复消耗 API，也不因提速丢失审计依据。

## 运行契约

1. 初始匹配输出 `review_queue.xlsx` 和 `debug/queries.jsonl`。
2. 队列保存 `scope_match`、`review_group_key`、`review_group_count`、`codebook_version`、`model_version` 和 `pipeline_stage`。
3. 人工审核只对 `scope_match=True` 的记录建立卡片；相同 `review_group_key` 只建立一张卡片，保存时作用于该组全部 `record_id`。
4. 人工审核完成后生成独立阶段文件。原始输入文件不被覆盖。
5. 变动审核使用用户当前选择的 codebook 和上传的阶段文件。若人工审核改过 codebook，必须重新选择最新 codebook。
6. 变动审核只生成报告和扩行建议，不自动修改阶段文件。
7. post_rank 审核必须接收人工确认后的变动审核文件，并通过安全校验后生成最终成稿。

## Checkpoint 1：输入版本

- [x] 阶段文件和 codebook 独立输入。
- [x] 审核队列记录 codebook 哈希和模型版本。
- [ ] 进入变动审核时比较阶段文件的来源版本与当前 codebook；版本不同应显示提示并要求用户确认。

风险：如果 codebook 修改后仍使用旧审核队列，旧的范围和分组字段可能过期。变动审核本身会重新读取当前 codebook，因此不使用旧队列字段；人工审核队列需要在版本不一致时重新生成。

## Checkpoint 2：审核范围

- [x] 初始审核队列生成 `scope_match`。
- [x] 旧队列没有该字段时保留兼容计算。
- [x] 变动审核仍按当前 codebook 的 cityname/distname 判断范围。

范围判断是安全边界，不能删除。优化点是把初始人工审核的范围判断从页面移到队列生成阶段，避免重复扫描 codebook。

## Checkpoint 3：名称组

- [x] 初始队列生成 `review_group_key` 和 `review_group_count`。
- [x] 新队列按预生成键分组。
- [x] 旧队列按原有字段兼容分组。

名称组键包含原始名称、地理范围、已有编码、问题类型和候选集合，避免把办公室等不同部门错误合并。保存仍以组内全部 `record_id` 为作用范围。

变动审核内部还按标准 `w_name` 分组，并对每个名称组的地理组合缓存适用的 codebook 有效期段；仅年份变化的部门再按 `(cityname, distname, year)` 缓存覆盖段；覆盖 2020 年的 `wrank20` 选择按 `(标准名称, cityname, distname)` 缓存。月份节点拆分仍按完整人员任职组逐组计算，以保留跨节点边界。

## Checkpoint 4：变动分流

1. 读取阶段文件和最新 codebook。
2. 按 codebook 范围筛选。
3. 识别无有效期、仅年份有效期、具体月份有效期。
4. 无有效期部门直接检查 `wrank_t` 与 `wrank20`。
5. 仅年份有效期部门按 `year` 匹配有效期段。
6. 具体月份有效期部门按人员任职区间判断是否跨节点。
7. 只对跨节点人员生成拆分建议。
8. 生成名称有效期问题、变动阶段问题、扩行结果和演示样本。

风险：月份拆分是最重的步骤，不能为了提速跳过边界判断或合并原始年度行。可安全优化的是在进入月份拆分前按部门类型缓存 codebook 有效期段。

## Checkpoint 5：可追溯性

- [x] 队列保留原始 `record_id`、原始编码和系统建议。
- [x] 扩行结果保留 `_split_flag`、段开始、段结束和拆分日志。
- [x] 变动审核不自动写回用户文件。
- [ ] 为每次变动审核报告写入输入文件哈希、codebook 哈希和运行时间。

## Checkpoint 6：界面性能

- [x] 删除无业务作用的 `_load_preview()`。
- [x] 结果预览改为流程检查清单。
- [x] 选择阶段文件后先让 Qt 绘制状态，再开始审核。
- [x] 变动审核显示阶段进度。
- [x] 范围筛选使用精确地域组合集合和空值通配列表，避免每条数据扫描整个 codebook。
- [x] 变动审核的演示样本生成已移除；完整处理结果和拆分日志仍保留在导出文件中。
- [x] 仅年份有效期和 2020 年 `wrank20` 选择使用组内缓存。
- [ ] 将 `process_codebook_data()` 移入后台线程，并通过回调显示部门组级进度。
- [ ] 取消大表 `resizeColumnsToContents()`，使用固定列宽。

当前剩余的主要性能风险是月份有效期拆分仍在界面线程执行。它影响响应速度，但不改变结果。迁移到后台线程时必须保证只在主线程更新 Qt 控件。

## 兼容性审阅

- 新队列字段都是附加字段，不改变原有字段名称和顺序。
- 旧队列缺少新字段时仍使用兼容分支。
- 阶段 Excel 仍按原有输入格式读取，未要求用户重新生成文件。
- codebook 修改后变动审核使用当前路径中的最新文件。
- 原始数据、人工阶段文件、变动审核报告和最终成稿保持独立。

## 当前结论

范围缓存和名称组缓存可以安全使用，能减少人工审核页面的重复计算。不能删除范围过滤和名称组合并，因为它们分别承担地理范围安全边界和重复记录合并审核的业务职责。下一阶段应优先实现版本一致性检查、后台变动审核线程和部门组级进度回调。
